# Stack high-water comparison (QEMU, sentinel-fill measurement)

Method: fill [_stack_end, sp - 1KB) with 0xAA before 30 inference runs,
scan for the deepest non-sentinel byte after; stack = _stack_start - deepest.
Arena from the build-time report; peak RAM = arena + stack high-water.

## Cortex-M4 (mps2-an386), MCUNet
| | standard | vMCU auto |
| --- | --- | --- |
| arena | 119,552 B | 34,880 B |
| stack high-water | 38,368 B | 47,272 B |
| peak (arena + stack) | 157,920 B | 82,152 B (-48%) |

## Cortex-M7 (mps2-an500), MCUNet
| | standard | vMCU auto |
| --- | --- | --- |
| stack high-water | 38,368 B | 47,272 B |

## Cortex-M4, LeNet5
| | standard | vMCU auto |
| --- | --- | --- |
| arena | 5,184 B | 5,184 B |
| stack high-water | 10,880 B | 10,880 B |

## Analysis (objdump-verified)

Frame-size audit of both binaries (largest `sub sp, sp, #N`):

- Standard: only main() has a large frame (37,120 B); the IREE dispatchers
  use the arena and have small frames.
- vMCU: same main() frame (37,120 B) plus per-dispatch frames 8,832 /
  8,576 / 7,328 / 6,880 / 6,304 / 5,280 / 5,152 ... owned by the
  `main_dispatch_*_custom_op_*` wrappers.

Sources of the stack:

1. main()'s 37,120 B frame is identical in both variants (example code,
   not vMCU-specific). It contains the per-iteration `InputTensor::new(7)`
   local (12,288 B; the model input is a value type) plus the benchmark
   and printing machinery; it is NOT the vMCU-vs-standard difference.
2. The vMCU-only difference (~9 KB at the high-water mark) comes from the
   IREE custom-op dispatch wrappers: each ukernel call's scratch/segment
   and non-in-place output buffers are allocated on the dispatcher's own
   stack frame (the frame sizes match the scratch sizes, e.g. 8,448 B
   segment). The toolchain permits up to 64 KiB of dispatch-local stack
   (--iree-llvmcpu-stack-allocation-limit=65536).
3. The vMCU C ukernels themselves use only small fixed frames.

LeNet5: both modes sit at 10,880 B (its dispatches have no large frames).

Even with the stack counted, vMCU peak RAM is 82 KB vs 158 KB standard
(-48%). The ukernel scratch is placed on the dispatch stack by IREE's
bufferization; moving it into the arena (or lowering the dispatch stack
limit) is a further tuning lever.

## Static stack budget (frame audit of both binaries)

vMCU binary frames (all `sub sp, sp, #N` >= 512):

   37,228  main (run() inlined; includes the 12,288 B input local
             and the timing/printing machinery)
    8,832  main_dispatch_5_custom_op_4608xi8   (ukernel dispatch)
    8,576  main_dispatch_4_custom_op_8448xi8   (ukernel dispatch)
    7,328  main_dispatch_14_custom_op_96x240xi8
    6,880  main_dispatch_15_custom_op_480x96xi8
    6,304  main_dispatch_16_custom_op_160x384xi8
    5,280  main_dispatch_11_custom_op_7x7x120x1xi8
    5,152  main_dispatch_7/8_custom_op_3456xi8
    4,640  main_dispatch_6_custom_op_4480xi8
    4,384  main_dispatch_13_custom_op_192x48xi8
    3,680  main_dispatch_10_custom_op_160x40xi8
      624  main_dispatch_0_custom_op_1x32x32x16xi8
      516  oneliner_vmcu_ibn_s8 (ukernel wrapper; conv2d/fc <= same)

The ukernel wrappers hold the scratch/segment and non-in-place output
buffers on their dispatch frames. Worst-case single path:
main 37,228 + deepest dispatch 8,832 + ukernel 516 + padding ~ 46.6 KB,
matching the measured 47,272 B high-water.

Standard binary: only main has a frame >= 512 (37,120); all dispatchers
use the arena and keep small frames, so the static worst case is ~38.4 KB
(matching the measured 38,368 B). The stack region (RAM top, 512 KiB
linker grant) is far from exhausted in either mode.
